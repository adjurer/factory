# AGENTS.md — 맥미니에서 도는 Codex 작업 규칙

이 문서는 **`macmini-codex-bot/` 폴더에서 도는 Codex(OpenAI CLI 에이전트)가 매 실행마다 따르는 지시서**입니다.
사람이 읽어도 되지만, 기준은 "Codex가 이 규칙만 보고 같은 결과를 만든다"입니다.

---

## 0. 한 줄 요약

`../feed/`에서 새 글감(쿠팡 파트너스 숏폼 1세트)을 읽고, **그 글감에 없는 수치를 만들지 않으면서**
숏폼 스크립트·자막·블로그 확장 글·카드뉴스 문구를 `output/{글감 id}/`에 추가한다.

## 1. 너의 범위

- 쓰기 가능: `output/{id}/` 안, 그리고 `state/`(스크립트만) — 그 외는 **읽기 전용**
- 절대 수정 금지: `../feed/**`(글감 원본), `../.git/**`
- 절대 건드리지 말 것: 이 저장소 밖의 다른 저장소(`adjurer.github.io`, `hermes-agent`, `2026win`,
  `cardnews-creator`, `live-speech-hub` 등)와 사용자의 다른 프로젝트
- 이 저장소는 **PUBLIC**이다. API 키·토큰·비밀번호·집주소·전화번호를 어떤 파일에도 쓰지 않는다.

## 2. 실행 절차 (매번 이 순서)

1. `git -C .. pull --ff-only` — 저장소 최신화(스크립트가 이미 한다. 실패해도 로컬 데이터로 계속).
2. `../feed/index.json` 을 읽는다. 없으면 `../feed/*/**.json` 을 직접 훑는다.
3. `state/processed_ids.json` 의 `ids` 키와 비교해 **아직 없는 id** 만 대상으로 삼는다.
4. 대상마다 `output/{id}/` 를 만들고 아래 5번 산출물을 채운다.
5. 다 끝나면 `state/processed_ids.json` 에 `{id: {processed_at, out}}` 를 추가한다.

> 이 절차는 `python3 scripts/codex_sync.py --run-codex` 한 줄로 자동 실행된다.
> 수동으로 할 때도 위 순서를 지켜라. `--dry-run` 은 상태를 저장하지 않으므로 다음 실행에서 다시 만들어진다.

## 3. 읽는 파일

| 파일 | 쓰임 |
|---|---|
| `../feed/index.json` | 전체 글감 목록(최신순). `items[].path` 가 원본 경로 |
| `../feed/latest.json` | 가장 최근 1건의 전체 내용 |
| `../feed/{YYYY-MM-DD}/{id}.json` | 글감 1건의 원본. **모든 수치의 유일한 출처** |
| `../feed/SCHEMA.md` | 필드 정의. 모르는 필드가 있으면 여기부터 |
| `output/{id}/manifest.json` | 이 글감의 요약·생성 시각 |
| `output/{id}/shorts_package.md` | 이미 조립된 본문·댓글·체크리스트(그대로 써도 됨) |
| `output/{id}/captions.srt` | 자동 자막 초안(고쳐야 하는 대상) |

## 4. 산출물 계약 (파일명 고정)

`output/{id}/` 안에 아래 이름으로 만든다. 이름을 바꾸면 스크립트·사람이 못 찾는다.

| 파일 | 내용 |
|---|---|
| `shorts_script.md` | 훅 3안(각 2줄) + 20초 타임라인(0~3s/3~8s/8~15s/15~20s) + 직접 촬영 컷 리스트 3컷 이상 |
| `captions.srt` | 영상 길이에 맞춘 자막. 큐 5개 이하, 한 줄 20자 안팎, 타임코드 형식 `00:00:00,000 --> 00:00:05,000` |
| `blog_draft.md` | H1 + H2 3~4개, 900~1,300자, 정보형 존댓말. 도입(문제)→사용 관점→스펙 표→주의→링크→대가성 |
| `hotdeal_card.md` | 카드뉴스 5장 문구(표지/문제/제품/스펙·주의/링크·대가성), 장당 2줄 이내 |
| `codex_output.md` | 무엇을 만들었는지 5줄 요약 + 사람이 확인해야 할 항목 |

## 5. 문체 규칙

- **숏폼(스레드·X·릴스)**: 짧은 입말 반말, 호들갑 톤(`ㅋㅋ`, `😭`, `!!!!`)은 원본 카피의 결을 유지.
  한 줄 30자 안팎, 줄바꿈으로 끊는다. 이모지는 줄당 1개 이하.
- **블로그**: 정보형 존댓말(`~습니다`). 표는 스펙 3~6행. 광고 문구 남발 금지, 과장 최상급 금지.
- **카드뉴스**: 한 장에 한 메시지. 숫자는 굵게 쓰지 말고 문장으로.
- 금지 표현(이른바 "AI 말투"): "결론적으로", "다양한 측면에서", "~할 수 있습니다만",
  "도움이 되셨길 바랍니다", "살펴보았습니다"로 시작하는 상투적 도입, 같은 문장구조 반복.
- 사용자(경원 님)가 싫어하는 것: 판매자 광고 같은 문장, 근거 없는 칭찬, 정렬 안 맞는 표. 표는 열을 맞춘다.

## 6. 사실 규칙 (가장 중요)

- **글감 JSON에 있는 값만 사실로 쓴다.** 가격·할인율·리뷰 수·평점·배터리 시간·소재를 새로 만들지 않는다.
- 없는 값은 `확인 필요`라고 쓴다. 추정하면 `추정`이라고 명시한다.
- `disclosure`(대가성 문구)는 **원문 그대로** 넣는다. 문구를 줄이거나 바꾸지 않는다.
- `caveats` 항목은 하나도 빠뜨리지 않는다. 특히:
  - 영상-상품 불일치(무선/유선, 다른 모델, 다른 규격)
  - 가격 기준일(파트너스 카드 기준가)
  - 저작권(남의 크리에이터 영상 — 재업로드 금지)
- "조회수 2,250만" 같은 수치는 `rights.metrics` 에 있는 것만, 확인 시점과 함께 쓴다.
- 영상 속 제품과 링크 상품이 **같은 모델이라고 단정하지 않는다**. 글감에 적힌 수준(형태 대조/동일 방식)만 쓴다.

## 7. 금지 행동

- ❌ SNS·블로그에 **직접 게시하지 않는다**. 초안까지만. 게시는 사람이 한다.
- ❌ 결제·구매·장바구니·회원가입을 하지 않는다.
- ❌ 남의 영상을 다운로드해 다시 올리는 것을 전제로 한 문구("그대로 올리면 됩니다")를 쓰지 않는다.
- ❌ `../feed/**` 를 고치거나 `git push` 하지 않는다(글감 발행은 상위 저장소를 운영하는 쪽 몫).
- ❌ `.env`, 키, 쿠키, 세션, 개인정보를 파일·로그·커밋에 남기지 않는다.
- ❌ 이 저장소 밖 파일을 읽거나 쓰지 않는다.

## 8. 실패·로그

- 피드가 비었으면 아무것도 만들지 말고 `새 글감 없음`만 남긴다(빈 파일 생성 금지).
- 한 글감에서 실패해도 다음 글감은 계속 처리한다. 실패한 id 는 `state`에 넣지 않는다(다음 실행에서 재시도).
- 스크립트 로그: `logs/codex-sync.log`(launchd), codex 출력: `output/{id}/codex_output.md`,
  codex 표준오류: `output/{id}/codex_stderr.log`.

## 9. 자주 쓰는 명령

```bash
cd ~/factory/macmini-codex-bot
python3 scripts/codex_sync.py --dry-run                 # 초안만 만들고 상태 저장 안 함
python3 scripts/codex_sync.py --dry-run --id 20261120_1700
python3 scripts/codex_sync.py --run-codex               # 실제 처리 + codex 호출
python3 scripts/codex_sync.py --json | jq '.new'        # 자동화에서 결과만 보기
tail -f logs/codex-sync.log
```
